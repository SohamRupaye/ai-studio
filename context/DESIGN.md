# DESIGN.md — AI Studio design system & component library

Context doc for whoever (human or agent) builds UI next. Everything described here is **implemented and working** in `apps/desktop/src/renderer/` — this is not a proposal. Read this instead of re-deriving the design system; read `ONBOARDING.md` for project-wide context.

State as of 2026-07-07: tokens + 31-component library complete and demoed in a dev gallery (`components/ui-gallery.tsx`, at the `/gallery` route). **App shell, settings area, and the chat page are built and user-approved** (committed — see `git log`). Remaining destination pages (Home, Memories/Artifacts, Knowledge graph, Compare, Costs) are placeholders.

**This is a living system, not a spec.** Improve it when a real use case demands it — several of today's best decisions (raised selects, the `*-text` badge tones, the glow) came from exactly that kind of revision. The distinction that matters: *evolve with a reason* (a page needs something the system doesn't do well) vs. *relitigate settled taste* (the warm-mono palette, the one-hero rule, mono-for-data — those stay unless the user reopens them). When you change tokens or component behavior, add a dated entry to the **Changelog** at the bottom of this file saying what changed and why, so the next iteration inherits the reasoning and not just the diff.

## Design direction (settled — don't relitigate)

The user (Soham) rejected two earlier UIs for looking "AI-generated": flat neutral gray, evenly-weighted panels, colored icon chips, generic admin layouts. Reference points: Dia, Arc, Wise, Notion, Sana.

**Rules that survive any redesign:**
- One hero moment per screen (the composer on chat; one primary button anywhere else).
- Depth comes from the **elevation ramp**, never decoration. Raised = lighter.
- Mono font **only for data in content**: model names, tokens, costs, branch names, numbers. Never prose. **Navigation rows are uniform sans regardless** — the user overruled mono branch names in the sidebar tree (read as inconsistency, not information); a small icon carries the row's identity instead.
- No colored icon chips. Color must mean state, not category.
- Sentence case everywhere.
- Every interactive element gets entrance/press micro-animation.
- **Palette is WARM MONO.** This superseded an earlier navy+ember direction after a side-by-side (`design-comparison.html` in repo root). Do not resurrect ember/navy without the user asking — older docs mentioning an Ember accent are stale.

## Tokens (`globals.css`)

All tokens are CSS variables set on `:root` (light, default) and `.dark`, mapped into Tailwind v4 via `@theme inline`. Theme switching = `.dark` class on `<html>` (`hooks/use-theme.ts`, system-follow default).

### Color — warm mono

Black/white/gray only, every gray warmed ~4% toward amber ("candlelit, not clinical").

- **Elevation ramp:** `canvas` (page, dark `#121110` / light `#F6F5F2`) → `surface-1` → `surface-2` → `surface-3`. Raised = lighter. `sunken` exists but is used **only** for the switch track (see field history below).
- **Text:** `fg` (dark mode `#DCDAD6` — deliberately not white), `fg-muted`, `fg-subtle`.
- **Lines:** `line`, `line-strong` (hover/focus border step).
- **Primary** (the hero action): soft warm gray — dark `#CBC8C1`, light `#33302A` — with `primary-fg`, `primary-hover`, `primary-active`. Never pure white/black.
- **Status triads:** `info|success|warning|danger` each have: solid (`--danger`), soft tint (`--danger-soft`), and **`--danger-text`** — a text-on-tint tone (darker than solid in light mode, brighter in dark). Badges use soft + text; buttons/alerts use solid/soft. Light-mode danger is a soft vermilion `#DD4938`, not harsh red.
- **Viz palette:** `viz-1`…`viz-8` for charts.

### Shadows

`shadow-xs/sm/md/lg/xl` ramp, plus semantic: `shadow-raised` (subtle lift; includes 1px inset top-light in dark), `shadow-sunken` (inset), `shadow-float` (floating hero elements, e.g. composer), `shadow-glow` (**focus glow for the hero composer** — warm emitted light in dark mode, halo-ring + deepened ambient in light mode; never blue).

### Radius — soft scale

`xs 4 / sm 8 / md 10 / lg 16 / xl 20`. Controls → `rounded-md`; cards/panels → `rounded-lg`; modals/drawers/floating popups → `rounded-xl`; composer & chips → pills. **Nesting rule: inner radius = outer radius − padding** (e.g. menu popup 16px − 6px padding = 10px items; tabs list 10px − 4px = 6px indicator).

### Typography

Mona Sans Variable (`@fontsource-variable/mona-sans/wdth.css`, bundled). Body is 14px with −0.006em tracking.

Tailwind text utilities (registered in `@theme`): `text-heading-lg/md/sm` (26/22/18, weight **600** — 700 is reserved for the one hero moment), `text-body-lg/md/sm` (16/14/12 at 400), `text-label-lg/md/sm` (14/13/11 at 500 — buttons, tabs, menu items, badges, table headers).

### Motion

- Easings: `--ease-standard`, `--ease-decel` (arrivals), `--ease-accel` (exits), `--ease-spring` (touch response). Rule: things ARRIVE decelerating, LEAVE accelerating, respond to touch with spring.
- Durations by convention: 50 press · 100 hover · 200 most · 300 entrances · 500 emphasis.
- Keyframes: `rise`, `pop`, `typing`, `fade-in/out`, `slide-in/out-right|left|bottom` (slide distances include the drawer's floating inset).
- Utilities: `pressable` (see gotcha below), `skeleton` (opacity pulse, no shimmer), `stagger-children` (list entrances, 30ms apart).
- `prefers-reduced-motion` globally collapses all animation.
- Focus: keyboard-only ring (`:focus-visible`, mono low-alpha). Disabled: universal fade via `:disabled`/`aria-disabled`.

## Three hard-won gotchas (violating these WILL reintroduce fixed bugs)

1. **`pressable` owns the entire interaction transition** (transform + colors + shadow + opacity). Never stack a `transition-*` utility on a pressable element — the CSS shorthand conflict silently kills one of the animations. If an element needs press feedback + color transitions, `pressable` alone already does both.
2. **tailwind-merge is extended in `lib/utils.ts`** to know our custom `text-*` tokens are font *sizes* and `shadow-raised/sunken/float/glow` are shadows. Without that registration it classified `text-label-md` as a *color* and silently dropped `text-primary-fg`/`text-white` from buttons (invisible-label bug). If you add new custom `text-*` or `shadow-*` theme tokens, **register them there too**.
3. **`MenuLabel`/`ContextMenuLabel` must sit inside a `MenuGroup`/`ContextMenuGroup`.** They're Base UI `GroupLabel` parts, which throw ("Menu group parts must be used within <Menu.Group>") when the popup mounts — and since popups mount on open, the crash presents as a blank screen on right-click, not at render time.

## Stack decisions

- **Base UI (`@base-ui-components/react`), NOT Radix.** Radix is unmaintained; all `@radix-ui/*` deps were removed — don't reintroduce them. Base UI conventions: parts are `Root/Trigger/Portal/Positioner/Popup`; custom element injection is the **`render` prop** (not `asChild`); state attrs are `data-checked`, `data-popup-open`, `data-highlighted`, and — careful — tabs use **`data-active`**, not `data-selected`. Animations: keyframes on `data-[open]`/`data-[closed]`, or transitions with `data-[starting-style]`/`data-[ending-style]`.
- **`@shadcn/react`** (shadcn's new headless primitives pkg) provides the message-scroller. It currently ships only that.
- **cmdk** powers the command bar (inside a Base UI dialog); **sonner** powers toasts (restyled `unstyled`).
- **Phosphor icons** — imports MUST use the `*Icon`-suffixed names (`CopyIcon`, not `Copy`; bare names are deprecated). Selected-state pattern: `weight={selected ? "fill" : "regular"}`.
- Button `asChild` uses a local ~10-line Slot in `button.tsx` (React 19 ref-as-prop).

## Changelog

Dated entries, newest first: what changed and **why**. Add one whenever tokens or component behavior change.

### 2026-07-13 (later) — Tool calls open up: salient rows, expandable detail, live Thinking

- **Why (user, with screenshots)**: rows still read as a black box — `web_fetch` without the URL, `bash` × 8 without the commands, and model reasoning invisible entirely. The raw-JSON `argsPreview` from the morning was a stopgap, not an answer.
- **Rows lead with the salient argument, not JSON**: `bash npm test`, `web_fetch https://…`, `web_search rust async runtime` — via the shared `toolCallSummary` (same function main persists, so live and reopened rows are identical; backend in ONBOARDING). Mono 11px `fg-subtle`, truncating, exactly where the JSON preview used to sit.
- **Rows are buttons → inline detail panel** (`ToolCallRow`): clicking expands Input (pretty JSON, or the bare command/reasoning for single-string-arg tools) and Result blocks — mono 11px `pre-wrap` in `surface-1` bordered blocks, `max-h-56` scroll, danger-tinted when the call failed, `… [truncated]` markers when capped. A trailing caret appears on hover (always visible when open) as the affordance; rows without stored detail (pre-existing messages) stay plain rows. Detail expansion is inline, not a Drawer — a tool call is a glance ("what did that run"), not a reading surface like the subagent transcript.
- **Thinking block** (`ThinkingBlock`): model reasoning streams live above the tool list — spinner + "Thinking…" while the model reasons, auto-open until the answer text starts, then it collapses out of the way (a user toggle always wins). Persisted messages render the same block collapsed with a Brain icon. Body is muted `body-sm` Markdown behind a hairline left border — reasoning reads as an aside, not a second reply. TypingDots now waits for text *and* thinking to be absent.
- Streaming: thinking deltas ride the same rAF frame-batch as text; `tool_end` now preserves the row's summary/args (it used to rebuild the entry and drop the preview) and attaches the result.
- **Same-day iteration (user: "we don't need this much detail all the time")**: Settings → General gained a **Chat section with a "Tool call details" Switch** — off hides the input/output expansion (no caret, rows not clickable); the salient one-liner stays either way, since "which URL did it fetch" was the original ask. Renderer-only pref (`toolCallDetail` in `UiPrefsProvider`, `ai-studio:tool-call-detail` in localStorage, on by default) — deliberately NOT config.yaml: it's per-device presentation, like sidebar state, not model behavior.

### 2026-07-13 — Tool rows say what they did

- **Why**: eight identical `bash` rows answered nothing — and the model itself, asked "what commands did you run?", denied running any (its past tool calls never re-entered context; backend fix in ONBOARDING). The UI half:

### 2026-07-12 (later) — Skills become real: settings page, slash commands, transcript chips

- **Why**: skills had zero user surface — the composer's attach-menu "Skills" item was a dead label and there was no way to see, add, or invoke one. Backend (single SKILL.md format, import/URL install, `skill` tool + `<available_skills>`, `/name` resolution in chat:send) is in ONBOARDING; the UI:
- **`/settings/skills`** (General nav group, after MCP servers; `LightningIcon`): installed skills as a row-group — `/name` in mono (the invocation IS the identity), description as the hint line ("No description — the model won't discover this skill on its own." when missing; "Slash-only" prefix for `disable-model-invocation` skills), **enabled Switch** per row, ⋯ menu (View instructions → read-only Markdown in a right-side **Drawer** (560px) — skill bodies are long reference documents, and the Dialog-vs-Drawer rule puts reading surfaces in drawers, same call as the subagent transcript; a centered modal was tried first and read cramped / Show in Finder / Remove… with ConfirmDialog naming the on-disk deletion). Section actions live on the **title row, not below the list** (user feedback with 30+ skills installed: scrolling to a footer to add is bad UX) — Rescan (ghost icon, spins while running; manual fallback to the file watcher via new `skills:reload` IPC) · Import · Add from URL, right-aligned via a new optional `actions` slot on `SettingsSection`. The skills page also widens the settings column (`max-w-3xl` vs the standard `2xl`) — mono names + sentence descriptions earn it. The original bottom split-button row was replaced the same day.
- **Add-from-URL is a two-step pick flow** (same-day iteration — skills ship as GitHub repos via skills.sh / `npx skills add <repo> --skill <name>`, so a bare URL install was the wrong shape): paste a GitHub repo / SKILL.md / catalogue URL → **Find skills** lists everything discovered (mono `/name`, description, already-installed rows disabled with an "Installed" badge, new ones pre-checked) → **Install N skills**. The pick-list IS the `--skill` flag. Editing the URL resets the list; backend discovery is in ONBOARDING.
- **Composer slash autocomplete**: a leading `/` opens an anchored panel above the composer (same popup language as menus: surface-2, shadow-float, 16−6→10 radius) listing enabled skills — mono `/name` + truncated description, prefix-filtered as you type, ↑/↓ + Enter/Tab select, Esc dismisses (typing revives). Selecting writes `/name ` into the draft — **deliberately no chip in the composer: the message text itself is the command**, which is also exactly what persists and what main parses; nothing to drift. The attach menu's Skills item opens the same panel in browse mode (all enabled skills, selection prefixes the draft); its empty state links to Settings → Skills. A bare `/token` matching nothing hides the panel — Enter sends the text as-is (paths like `/etc/hosts` never bounce).
- **Transcript chip**: user turns starting with `/name` (matching an installed skill) render the token as a small Lightning pill above the message text — derived from content at render time, applied to both persisted and optimistic bubbles. Chips survive a skill being disabled (installed names, not enabled ones).
- **`Composer` grew a `textareaRef` prop** (escape hatch to the inner textarea) so pickers that insert text can refocus it — first consumer is the skill panel.
- Live updates: `skills:changed` listener in App.tsx (same pattern as `mcp:changed`) — an external edit to the skills dir refreshes every mounted list.

### 2026-07-12 — Subagent detail: dialog → non-modal drawer with the full live transcript

- **Why (user feedback on the live dialog)**: "Working…" answered nothing — only tool *names* streamed, no text, no args; and a modal blocks the chat you're waiting on. Also a delegate job ran 3+ minutes with no elapsed indication (backend added hard timeouts — see ONBOARDING).
- **The detail surface is now a Drawer, not a Dialog** — our own rule (Dialog = confirmations/focused forms, Drawer = reference panels) already said so: right side, `modal={false}` and **no backdrop** (`DrawerContent` gained `showBackdrop`), so the chat stays visible and interactive while agents work.
- **The drawer shows the agent's entire process**: Task, then a live Transcript — the agent's own text rendered as Markdown, interleaved with tool cards (icon + name, args preview in mono, `→ result preview`, danger tint on failure, spinner on the in-flight call), auto-following while running. Built from the same `steps` the message persists, so reopening later shows the identical transcript. A separate Result section renders only for records persisted before transcripts existed.
- **Elapsed time everywhere**: agent rows and the drawer header tick live (`Elapsed`) while running and show the persisted duration after — a stuck run is now visibly stuck, and timed-out runs say "Timed out after Ns".

### 2026-07-11 (evening) — Subagents become visible: per-agent rows + a detail dialog
